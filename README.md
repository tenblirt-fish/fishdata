# 🐟 Alaska Sockeye Daily — Bristol Bay 2026

Публичная страница с ежедневной автообновляемой сводкой по вылову нерки на Аляске.
Двуязычная (русский / 日本語). Полностью бесплатный хостинг через GitHub Pages.

**Что обновляется автоматически в 09:00 МСК каждый день:**
- Свежий Blue Sheet (PDF) с сайта ADF&G — скачивается и хостится локально
- Цифры вылова по 5 районам Bristol Bay (Naknek-Kvichak, Egegik, Ugashik, Nushagak, Togiak)
- Накопленный вылов по сезону
- Новости из 5 RSS-источников (SeafoodSource, KDLG, Undercurrent News, Alaska Public Media, IntraFish) — отфильтрованные по ключевым словам
- Пресс-релизы ADF&G
- Архив всех ежедневных снимков в `data/history/YYYY-MM-DD.json`

## 🚀 Запуск за 15 минут

### Шаг 1. Создать репозиторий на GitHub

1. Зайдите на [github.com](https://github.com), войдите в аккаунт (или зарегистрируйтесь)
2. Нажмите **New repository** (зелёная кнопка)
3. Заполните:
   - **Repository name:** `alaska-sockeye-daily` (или любое имя)
   - **Public** ✅ (обязательно, иначе GitHub Pages потребует платный план)
   - **Add a README** ❌ (НЕ ставьте — у нас уже свой)
4. Нажмите **Create repository**

### Шаг 2. Загрузить файлы

**Вариант А — через веб-интерфейс (проще):**

1. На странице нового пустого репозитория нажмите **uploading an existing file**
2. Перетащите все файлы из этого комплекта (сохраняя структуру папок)
3. Внизу нажмите **Commit changes**

**Вариант Б — через командную строку:**

```bash
git clone https://github.com/ВАШ_ЛОГИН/alaska-sockeye-daily.git
cd alaska-sockeye-daily
# скопируйте сюда все файлы из комплекта
git add .
git commit -m "Initial setup"
git push
```

### Шаг 3. Включить GitHub Pages (хостинг страницы)

1. В репозитории → **Settings** (вкладка вверху справа)
2. В левом меню → **Pages**
3. **Source:** выберите `Deploy from a branch`
4. **Branch:** `main` / `/(root)` → нажмите **Save**
5. Подождите 1–2 минуты. Сверху появится зелёная плашка с адресом:

```
https://ВАШ_ЛОГИН.github.io/alaska-sockeye-daily/
```

**Эту ссылку можно отправить кому угодно** — страница публичная.

### Шаг 4. Разрешить GitHub Actions писать в репозиторий

Это нужно, чтобы скрипт мог коммитить обновлённые данные обратно.

1. **Settings** → в левом меню **Actions** → **General**
2. Прокрутите вниз до **Workflow permissions**
3. Выберите **Read and write permissions** ✅
4. Нажмите **Save**

### Шаг 5. Запустить первое обновление вручную (проверка)

Не дожидаясь 9:00 МСК — давайте проверим, что всё работает:

1. Вкладка **Actions** (вверху репозитория)
2. Слева — **Daily Sockeye Update**
3. Справа — кнопка **Run workflow** → **Run workflow** (зелёная)
4. Через 1–2 минуты у workflow появится зелёная галочка ✅
5. Откройте свою страницу — данные обновлены

Если красный крестик ❌ — кликните на запуск, посмотрите логи, частые проблемы внизу README.

## ⚙️ Как это работает технически

```
┌─────────────────────────┐
│  GitHub Actions cron    │  каждый день 06:00 UTC (09:00 МСК)
│  '0 6 * * *'            │
└───────────┬─────────────┘
            ▼
┌─────────────────────────────────────────────────┐
│  scripts/fetch_data.py запускается в Ubuntu     │
│                                                 │
│  ① Скачивает Blue Sheet PDF с adfg.alaska.gov   │
│  ② pdfplumber парсит таблицы → цифры по районам │
│  ③ feedparser читает 5 RSS-лент новостей        │
│  ④ Фильтрует по ключам (sockeye/нерка/ベニサケ) │
│  ⑤ Извлекает числовые показатели через regex    │
│  ⑥ Сохраняет в data/latest.json + history/      │
└─────────────────┬───────────────────────────────┘
                  ▼
┌─────────────────────────────────────────────────┐
│  git commit + git push → main                   │
└─────────────────┬───────────────────────────────┘
                  ▼
┌─────────────────────────────────────────────────┐
│  GitHub Pages пересобирает сайт автоматически   │
│  index.html запросом fetch() читает latest.json │
│  → пользователь видит обновлённые данные        │
└─────────────────────────────────────────────────┘
```

## 🐞 Частые проблемы

**❌ Workflow падает с ошибкой `Permission denied to github-actions[bot]`**
→ Не выполнен Шаг 4 — включите Read and write permissions в Actions → General.

**❌ Blue Sheet PDF не скачивается**
→ Это нормально вне сезона. ADF&G публикует Bluesheet только в июне–августе.
   В межсезонье страница покажет «Blue Sheet появится после ~22 июня 2026» — это правильное поведение.

**❌ Новости пустые**
→ Проверьте, что RSS-источники доступны. SeafoodSource иногда меняет URL. Поправьте в `fetch_data.py` → `NEWS_FEEDS`.

**❌ Страница 404 после включения Pages**
→ Подождите 3–5 минут. Первая публикация может занять время.

**❌ Время обновления не 9:00 МСК ровно**
→ GitHub может задерживать cron на 5–15 минут в часы пиковой нагрузки — это нормально для бесплатного тарифа.
   Если критично — переходите на платный self-hosted runner или Vercel Cron.

**❌ Хочу другой источник новостей**
→ Добавьте в список `NEWS_FEEDS` в `scripts/fetch_data.py`. Формат: `("Название", "URL_RSS_ленты")`.
